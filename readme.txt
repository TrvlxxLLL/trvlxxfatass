# СухоVL

Народная карта стихийных происшествий Владивостока: житель ставит метку на карте,
указывает адрес, прикладывает фото и комментарий, остальные видят
предупреждение. Фото и комментарии проверяет vision-модель через gptunnel,
спорное решает разработчик вручную.

## Координаты центра карты

- Широта: 43.1155
- Долгота: 131.8855

## Карта и адреса

- Подложка: Яндекс Карты (MAP_PROVIDER=yandex, проекция EPSG:3395),
  запасной вариант — OpenStreetMap (MAP_PROVIDER=osm).
- Адрес по координатам: /api/geo/address, провайдер GEOCODER=nominatim
  (по умолчанию) или yandex с ключом YANDEX_GEOCODER_KEY.

## Переменные окружения (.env)

Скопируйте .env.example в .env и заполните:

- SECRET_KEY           — подпись сессий кабинета, 32+ символа (обязательно)
- GPTUNNEL_API_KEY     — ключ модели (или введите его в кабинете /dev)
- GIGACHAT_AUTH_KEY    — ключ авторизации GigaChat (или введите в /dev)
- AI_CA_BUNDLE         — путь к PEM с корневыми сертификатами (необязательно)
- DEV_LOGIN/DEV_PASSWORD — доступ в кабинет, по умолчанию dev / suhovl2025
- MAP_PROVIDER         — yandex или osm
- GEOCODER             — nominatim или yandex
- YANDEX_GEOCODER_KEY  — ключ геокодера Яндекса (если GEOCODER=yandex)
- COOKIE_SECURE=1      — если сайт работает по HTTPS
- TRUST_PROXY=1        — если спереди стоит свой nginx

Секреты в коде не хранятся: ключ берётся из базы (кабинет) или из окружения.

## Сценарий пользователя

1. На входе — выбор: сделать фото, отметить место на карте или
   просто открыть карту.
2. Уточнение места «как в такси»: карта двигается под неподвижной меткой,
   адрес подсказывается автоматически (GPS, иначе подсказка по IP,
   иначе центр города).
3. Форма сообщения: адрес (можно поправить), фото, комментарий.
4. Уведомление об успехе/ошибке, тексты редактируются в /dev.
5. Кнопка «+ Сообщить о происшествии» на карте запускает сценарий заново.

## Проверка фото и комментариев моделью

Поддержаны два провайдера, переключатель в /dev — «Провайдер»:

- openai   — любой OpenAI-совместимый chat/completions (gptunnel, gpt-4o-mini);
- gigachat — GigaChat Сбера.

Для GigaChat достаточно выбрать провайдера и вставить ключ авторизации:
адрес (https://gigachat.devices.sberbank.ru/api/v1/chat/completions) и модель
(GigaChat-2-Max) подставляются автоматически, пока в полях стоят
значения для gptunnel. Что происходит под капотом:

1. gigachat.py берёт временный токен на ngw.devices.sberbank.ru:9443
   (Basic-ключ + RqUID + scope) и кэширует его до истечения;
2. фото загружается в /api/v1/files (purpose=general), в сообщение уходит
   только attachments с идентификатором файла;
3. temperature поднимается до 0.1 — ноль GigaChat не принимает;
4. при HTTP 401 токен сбрасывается и берётся заново.

Галочка «Проверять TLS-сертификат GigaChat» по умолчанию снята: без
корневого сертификата Минцифры Python не доверяет доменам Сбера.
На gptunnel эта настройка не влияет. Если сертификат есть — положите PEM
и укажите путь в AI_CA_BUNDLE, затем включите галочку.

## Кабинет разработчика (/dev)

- Вход: ссылка «Кабинет разработчика» в шапке карты или /login.
- Аккаунт один, создаётся автоматически из DEV_LOGIN/DEV_PASSWORD при
  запуске приложения. Регистрации нет: меняем .env и перезапускаем.
- Вкладка «Модель и проверка»: endpoint, модель, ключ API, таймаут, лимит
  токенов, режим модерации (ИИ / вручную / без проверки), кнопка «Проверить
  связь».
- Вкладка «Промпты»: промпт проверки фото и промпт проверки комментария.
- Вкладка «Тексты уведомлений»: все сообщения, которые видит житель.
- Вкладка «Модерация»: очередь с фото, комментарием, вердиктами ИИ и
  кнопками одобрить/скрыть.
- Те же кнопки доступны в попапах карты при включённом «Режиме модерации».

## Локальный запуск без Docker

    python -m venv .venv
    .venv\Scripts\activate
    pip install -r requirements.txt
    python app.py

## Запуск в Docker

    docker compose up -d --build
    docker compose logs -f web

## Демоданные

    python scripts/seed.py --reset        # 15 тестовых точек
